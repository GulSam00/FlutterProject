# 이슈 관리

작업할 이슈를 저장소 안의 파일로 관리한다. 이슈 하나 = 파일 하나
(`<YYYY-MM-DD>-<slug>.md`)이고, 파일 이름이 곧 이슈 ID다.
한 파일 안에 현재 상태, 배경, 완료 조건, 변경 로그(최신순)가 모인다.

- 새 이슈: `_TEMPLATE.md`를 복사한다. 날짜는 만든 날, slug는 내용을 알 수 있게 구체적으로 쓴다.
- 작업 절차와 변경 로그 형식: 루트 [`CLAUDE.md`](../../CLAUDE.md)의 "이슈 작업 절차"가 기준이다.
- 상태는 각 파일의 frontmatter `status`에만 적는다 (목록 파일을 따로 두면 두 곳이 어긋난다).

```bash
# 전체 상태 보기
grep -H '^status:' docs/issues/[0-9]*.md

# 진행 중인 이슈만
grep -l '^status: in-progress' docs/issues/[0-9]*.md

# 특정 이슈의 커밋 이력
git log --oneline --grep 'Issue: 2026-11-04-verify-tini-signal-handling'
```

## 이슈별 세션으로 작업하기

이슈 하나를 세션 하나에 맡기면 맥락이 섞이지 않고, 실패한 작업이 다른 이슈에 번지지 않는다.
Agent 가 스스로 세션을 만들어 작업을 넘기는 방식은 권장하지 않는다 (사람의 확인 없이 연쇄 실행이 된다).
**세션은 사람이 열고**, 아래 한 줄만 전달하면 된다.

```
docs/issues/<이슈 ID>.md 이슈를 CLAUDE.md "이슈 작업 절차" 대로 끝까지 처리해 주세요.
선택이 필요한 지점은 스스로 판단하고, 근거를 docs/temp/decision-log.md 에 남겨 주세요.
```

이 한 줄로 충분한 이유: 브랜치·커밋 형식·검증 명령·금지 사항·완료 판정 기준이 모두 저장소 안에 있다
(루트 `CLAUDE.md`, `apps/<app>/CLAUDE.md`, 그리고 이슈 파일 자체).

주의할 점

- **한 번에 하나씩** 진행한다. 여러 세션이 같은 브랜치에 push 하면 충돌하고,
  특히 루트 `CLAUDE.md` 와 판단 기록 파일을 동시에 고치게 된다.
- 뒤 이슈가 앞 이슈의 결과에 기대는 경우가 있다 (예: 생성기 템플릿 검증에는 웹 테스트 실행기가 필요하다).
  의존 관계가 있으면 순서를 지킨다.
- 클라우드 세션을 쓴다면 환경 Setup script 가 다른 프로젝트 경로로 `cd` 하다 실패하지 않는지 확인한다.
  실패하면 세션이 설정되지 않은 컨테이너로 시작한다 (README "Claude 클라우드 세션 설정" 참조).
